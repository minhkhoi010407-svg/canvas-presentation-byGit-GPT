# Quality standards

Use a recorded checklist with actionable findings; a binary score alone is not enough.

## Content

- [ ] Audience, purpose, and requested outcome are explicit.
- [ ] Narrative progresses logically; every slide has one useful takeaway.
- [ ] Material facts and numbers have traceable evidence and correct context.
- [ ] Terminology, spelling, language, and citations are consistent.

## Visual

- [ ] Every page was inspected as a rendered image, preferably as a contact sheet and at full size.
- [ ] No clipped, overlapping, off-canvas, unreadable, or unexpectedly wrapped content.
- [ ] Contrast, type size, alignment, density, image crops, and chart labels are legible.
- [ ] Layout and visual language are consistent without becoming monotonous.

## Editability and accessibility

- [ ] Output lane and editability expectation are stated.
- [ ] Requested editable text, shapes, charts, and reading order were checked in an Office-compatible viewer.
- [ ] Raster elements and unsupported features are disclosed.
- [ ] Alternative text and non-color meaning are provided where supported.

## Artifact

- [ ] Slide/page count, dimensions, and requested formats match the brief.
- [ ] Output opens in the intended viewer; fonts and linked assets are present or documented.
- [ ] Render/export logs contain no unresolved errors.
- [ ] Final package includes the source artifacts, provenance, and limitations that users need.

Record each item as `pass`, `fail`, or `not run`, with evidence. `Not run` must not be presented as a pass.
